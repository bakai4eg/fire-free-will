# ТЗ: Telegram-бот «Пожарная сводка»

## Зачем
Сайт нужен начальнику для плана на сезон. Бот нужен человеку на месте (МЧС, айыл окмоту, лесхоз): он получает **утреннюю сводку** и **оповещение о новом очаге** у себя в области, ничего не открывая.

## Что делает бот (MVP)
1. **Утренняя сводка**, каждый день в 08:00 по Бишкеку, отдельно по каждой области:
   - очаги за последние 24 часа;
   - очаги в этом месяце и норма (медиана за этот месяц), отклонение в %;
   - фаза сезона: «до пика / пик / спад» и в каком месяце пик;
   - **уровень риска на сегодня**: низкий, средний или высокий (календарь + погода);
   - ссылка на сайт, сразу открытый на этой области.
2. **Оповещение о новых очагах**, проверка каждый час: если в области появились новые точки, короткое сообщение с координатами и ссылкой на карту.
3. Сообщения отправляются в **Telegram-канал** (один на всю страну, область указана в тексте). Сервер не нужен: всё запускается через GitHub Actions.

**Дополнительно, если останется время:** интерактивный бот с командами `/start`, `/region`, `/today` и подпиской на свою область.

## Архитектура
```
FIRMS NRT API ──► bot/fetch_nrt.py ──► bot/out/nrt.json ─┐
Open-Meteo    ──► bot/weather.py   ──► bot/out/weather.json ─┼─► bot/engine.py ──► bot/out/digest.json, alerts.json ──► bot/send.py ──► Telegram
web/data/cells.json (история, уже есть) ─────────────────┘
bot/state/seen.json — какие очаги уже отправлены (чтобы не дублировать)
```
Язык: Python 3, только stdlib + `requests`. Секреты хранятся только в GitHub Secrets и **никогда** в коде:
`FIRMS_MAP_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.

## Человек A — движок (данные и логика)
**Файлы:** `bot/fetch_nrt.py`, `bot/engine.py`, `bot/regions.json`
1. `fetch_nrt.py`: качает свежие точки по bbox Кыргызстана (≈ `39.1,69.2,43.3,80.3`):
   `https://firms.modaps.eosdis.nasa.gov/api/area/csv/{MAP_KEY}/VIIRS_SNPP_NRT/69.2,39.1,80.3,43.3/2`
   (последний параметр — число дней, 1–10). Для оповещений можно добавить `VIIRS_NOAA20_NRT`, но для сравнения с нормой — **только SNPP**, потому что история гармонизирована под него. Фильтр: confidence `n`/`h`.
2. `engine.py`:
   - раскладывает точки по областям (точка внутри bbox);
   - `last24h` — точки за последние 24 часа;
   - `month_count` — точки за текущий месяц (из NRT; если не хватает дней, дополнить из `data/raw`);
   - `month_median` — медиана этого месяца за прошлые годы из `web/data/cells.json` (поле `h`, клетки внутри bbox);
   - `season_phase` — сравнить текущий месяц с месяцем пика (тот, у которого максимальная медиана);
   - `risk` — по формуле ниже, с погодой из `weather.json`;
   - `alerts.json` — точки, которых нет в `bot/state/seen.json`; после отправки их ключи (`lat,lon,date,time`) дописываются в seen.
3. **Формула риска** (простая эвристика, НЕ прогноз — так и пишем в сообщении):
   - сезон: медиана этого месяца / максимальная месячная медиана: ≥0.6 → +2, ≥0.3 → +1;
   - отклонение от нормы > +50% → +1;
   - tmax > 25 °C → +1; rh_min < 30% → +1; wind_max > 30 км/ч → +1; rain > 2 мм → −2;
   - итог: ≤1 «низкий», 2–3 «средний», ≥4 «высокий».
   - `risk_reasons` — человеческие причины для каждого сработавшего пункта.
- **Готово, когда:** `python bot/engine.py` на тестовых файлах (`bot/fixtures/`) выдаёт корректные `digest.json` и `alerts.json`, и повторный запуск не выдаёт те же оповещения второй раз.

## Человек B — Telegram (сообщения)
**Файлы:** `bot/send.py`, `bot/templates.py`
1. Создать бота через @BotFather и канал; добавить бота админом канала. Узнать `chat_id` канала.
2. `send.py --digest` и `send.py --alerts`: читают JSON и шлют через `https://api.telegram.org/bot{TOKEN}/sendMessage` (`parse_mode=HTML`, `disable_web_page_preview=true`). Ограничение Telegram: не больше ~20 сообщений в минуту в один канал, поэтому сводку отправлять **одним сообщением на всю страну**, а не 7 отдельными.
3. Шаблон сводки:
```
🔥 Пожарная сводка · 15 ноября

🟠 Чуйская — риск СРЕДНИЙ
   За сутки: 2 · За месяц: 12 (норма 8, ▲ +50%)
   Сезон: спад (пик в апреле)
   Почему: сухо (влажность 22%), выше нормы
   🗺 Открыть карту

🟢 Таласская — риск НИЗКИЙ
   За сутки: 0 · За месяц: 1 (норма 2, ▼ −50%)
...
Риск — оценка по истории 2000–2025 и прогнозу погоды, не точный прогноз.
Данные: NASA FIRMS (MODIS + VIIRS).
```
   Цвета: 🟢 низкий, 🟠 средний, 🔴 высокий. «Открыть карту» — ссылка `site_url`.
4. Шаблон оповещения:
```
🚨 Новый очаг · Чуйская
42.810, 74.520 · сегодня 10:12 (Бишкек)
Мощность: 7.3 МВт · уверенность: средняя
📍 Google Maps: https://maps.google.com/?q=42.81,74.52
```
   Если новых очагов в одной области больше 5, отправить одно сообщение «🚨 7 новых очагов в Чуйской» со ссылкой на сайт вместо 7 отдельных.
5. Флаг `--dry-run`: печатать сообщение в консоль вместо отправки (для тестов и чтобы не спамить канал).
- **Готово, когда:** на тестовых JSON в канал приходит сводка и оповещение, которые правильно выглядят на телефоне.
- **Дополнительно:** интерактивный бот (`bot/interactive.py`, long polling `getUpdates`): `/start` — приветствие и кнопки областей; `/today` — сводка по выбранной области; подписки в `bot/state/subscribers.json`. Запускать на ноутбуке во время демо.

## Человек C — погода и инфраструктура
**Файлы:** `bot/weather.py`, `.github/workflows/bot-digest.yml`, `.github/workflows/bot-alerts.yml`
1. `weather.py`: для центра каждой области запрос к Open-Meteo (бесплатно, без ключа):
   `https://api.open-meteo.com/v1/forecast?latitude=42.75&longitude=74.4&daily=temperature_2m_max,relative_humidity_2m_min,wind_speed_10m_max,precipitation_sum&timezone=Asia/Bishkek&forecast_days=1`
   Результат пишется в `bot/out/weather.json` в формате контракта.
2. GitHub Actions:
   - `bot-digest.yml`: `cron: '0 2 * * *'` (08:00 Бишкек) → `fetch_nrt` → `weather` → `engine` → `send --digest`;
   - `bot-alerts.yml`: `cron: '17 * * * *'` (каждый час) → `fetch_nrt` → `engine` → `send --alerts` → коммит `bot/state/seen.json` обратно в репозиторий (нужно `permissions: contents: write`);
   - оба с `workflow_dispatch`, чтобы на демо запускать вручную кнопкой;
   - секреты: `FIRMS_MAP_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (Settings → Secrets → Actions).
3. Сайт: добавить в `web/index.html` чтение параметра `?bbox=` из URL, чтобы ссылка из бота сразу открывала нужную область (согласовать с фронтендером).
4. Помнить: cron в GitHub Actions может опаздывать на 5–20 минут, это нормально. На демо запускать вручную.
- **Готово, когда:** кнопка «Run workflow» в Actions за 1–2 минуты присылает настоящую сводку в канал.

## План по времени
| Час | A (движок) | B (Telegram) | C (погода + инфра) |
|---|---|---|---|
| 0–1 | Вместе: утвердить контракты JSON, создать бота и канал, получить MAP_KEY | | |
| 1–4 | fetch_nrt + engine на тестовых данных | send.py + шаблоны на тестовых JSON (`--dry-run`) | weather.py + workflow-файлы |
| 4–6 | Риск, seen.json | Отправка в канал, проверка на телефоне | Секреты, первый запуск в Actions |
| 6–8 | **Сборка всего вместе**: один запуск от FIRMS до сообщения в канале | | |
| 8+ | Баги, точность областей | Интерактивный бот (доп.) | `?bbox=` на сайте, запись демо-видео с телефона |

## Чего НЕ делаем
- ML-прогноз «где загорится завтра».
- Свой сервер или базу данных.
- Больше одного канала.
